# API TaskFlow

Документация REST API проекта TaskFlow.

- Базовый префикс: `/api/v1`
- Формат данных: JSON
- Аутентификация: заголовок `Authorization: Bearer <токен>`. Все эндпоинты, кроме `POST /users` и `POST /tokens`, требуют токен.
- Права доступа указаны у каждого эндпоинта: `auth` — любой авторизованный пользователь, `admin` — только администратор.

## Модели данных

Объекты, которые возвращает API.

**User**

```json
{
  "id": 1,
  "email": "anna@mail.ru",
  "full_name": "Анна Иванова",
  "role": "user",
  "is_active": true,
  "created_at": "2026-11-19T10:00:00"
}
```

**Project**

```json
{
  "id": 3,
  "name": "Курсовая работа",
  "description": "Задачи по курсовой",
  "owner_id": 1,
  "created_at": "2026-11-19T10:05:00",
  "updated_at": "2026-11-19T10:05:00"
}
```

**Task**

```json
{
  "id": 7,
  "project_id": 3,
  "title": "Написать введение",
  "description": "Объём 1–2 страницы",
  "status": "todo",
  "priority": "medium",
  "assignee_id": 1,
  "due_date": "2026-11-25",
  "created_at": "2026-11-19T10:10:00",
  "updated_at": "2026-11-19T10:10:00"
}
```

Допустимые значения: `status` — `todo`, `in_progress`, `done`; `priority` — `low`, `medium`, `high`.

**Comment**

```json
{
  "id": 12,
  "task_id": 7,
  "author_id": 1,
  "body": "Начала писать, нужен план",
  "created_at": "2026-11-19T11:00:00"
}
```

## Авторизация и пользователи

### POST /users

Регистрация нового пользователя. Доступ: без авторизации.

Тело запроса:

```json
{
  "email": "anna@mail.ru",
  "password": "secret123",
  "full_name": "Анна Иванова"
}
```

Ответ (201 Created):

```json
{
  "id": 1,
  "email": "anna@mail.ru",
  "full_name": "Анна Иванова",
  "role": "user",
  "is_active": true,
  "created_at": "2026-11-19T10:00:00"
}
```

Ошибки: `409` — e-mail уже зарегистрирован, `422` — неверный формат данных.

### POST /tokens

Вход в систему, выдача JWT-токена. Доступ: без авторизации.

Тело запроса:

```json
{
  "email": "anna@mail.ru",
  "password": "secret123"
}
```

Ответ (200 OK):

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

Ошибки: `401` — неверный e-mail или пароль, либо аккаунт заблокирован.

### GET /users/me

Профиль текущего пользователя. Доступ: `auth`.

Ответ (200 OK): объект [User](#модели-данных).

### PATCH /users/me

Смена имени или пароля. Доступ: `auth`.

Тело запроса (все поля необязательные, но для смены пароля нужны оба пароля):

```json
{
  "full_name": "Анна Петрова",
  "current_password": "secret123",
  "new_password": "newsecret456"
}
```

Ответ (200 OK): объект [User](#модели-данных). Ошибка `403`, если текущий пароль указан неверно.

### GET /users

Список пользователей. Доступ: `admin`.

Параметры запроса: `limit`, `offset`.

Ответ (200 OK): массив объектов [User](#модели-данных).

### PATCH /users/{user_id}

Блокировка, разблокировка и смена роли. Доступ: `admin`.

Тело запроса (поля необязательные):

```json
{
  "is_active": false,
  "role": "user"
}
```

Ответ (200 OK): объект [User](#модели-данных).

## Проекты

### GET /projects

Список проектов, доступных текущему пользователю (владелец или участник). Администратор видит все проекты. Доступ: `auth`.

Параметры запроса: `limit`, `offset`.

Ответ (200 OK): массив объектов [Project](#модели-данных).

### POST /projects

Создание проекта. Текущий пользователь становится владельцем. Доступ: `auth`.

Тело запроса:

```json
{
  "name": "Курсовая работа",
  "description": "Задачи по курсовой"
}
```

Ответ (201 Created): объект [Project](#модели-данных).

### GET /projects/{project_id}

Карточка проекта. Доступ: владелец, участник, `admin`.

Ответ (200 OK): объект [Project](#модели-данных).

### PATCH /projects/{project_id}

Изменение проекта. Доступ: владелец, `admin`.

Тело запроса (поля необязательные):

```json
{
  "name": "Курсовая работа 2026",
  "description": "Новое описание"
}
```

Ответ (200 OK): объект [Project](#модели-данных).

### DELETE /projects/{project_id}

Удаление проекта вместе с его задачами и комментариями. Доступ: владелец, `admin`.

Ответ: `204 No Content`, тело пустое.

### POST /projects/{project_id}/members

Добавление участника в проект. Доступ: владелец, `admin`.

Тело запроса:

```json
{
  "user_id": 2
}
```

Ответ (201 Created):

```json
{
  "project_id": 3,
  "user_id": 2
}
```

### DELETE /projects/{project_id}/members/{user_id}

Исключение участника из проекта. Доступ: владелец, `admin`.

Ответ: `204 No Content`, тело пустое.

## Задачи

### GET /projects/{project_id}/tasks

Список задач проекта. Доступ: владелец, участник, `admin`.

Параметры запроса (все необязательные): `status`, `priority`, `assignee_id`, `overdue` (`true` — только просроченные), `sort`.

Пример запроса: `GET /api/v1/projects/3/tasks?status=todo&priority=high`

Ответ (200 OK):

```json
[
  {
    "id": 7,
    "project_id": 3,
    "title": "Написать введение",
    "description": "Объём 1–2 страницы",
    "status": "todo",
    "priority": "high",
    "assignee_id": 1,
    "due_date": "2026-11-25",
    "created_at": "2026-11-19T10:10:00",
    "updated_at": "2026-11-19T10:10:00"
  }
]
```

### POST /projects/{project_id}/tasks

Создание задачи в проекте. Доступ: владелец, участник, `admin`.

Тело запроса (обязательно только `title`):

```json
{
  "title": "Написать введение",
  "description": "Объём 1–2 страницы",
  "priority": "high",
  "assignee_id": 1,
  "due_date": "2026-11-25"
}
```

Ответ (201 Created): объект [Task](#модели-данных). Если `status` не указан, задача создаётся со статусом `todo`, если не указан `priority` — со значением `medium`.

### GET /tasks

Список и поиск задач во всех доступных проектах. Доступ: `auth`.

Параметры запроса (все необязательные): `q` (подстрока в названии), `status`, `priority`, `assignee_id`, `overdue`.

Пример запроса: `GET /api/v1/tasks?q=введение&overdue=true`

Ответ (200 OK): массив объектов [Task](#модели-данных).

### GET /tasks/{task_id}

Карточка задачи. Доступ: по доступу к проекту.

Ответ (200 OK): объект [Task](#модели-данных).

### PATCH /tasks/{task_id}

Редактирование задачи, смена статуса, назначение исполнителя. Доступ: владелец, участник, `admin`.

Тело запроса (любые поля задачи):

```json
{
  "status": "in_progress",
  "assignee_id": 2
}
```

Ответ (200 OK): объект [Task](#модели-данных) с обновлённым полем `updated_at`.

### DELETE /tasks/{task_id}

Удаление задачи вместе с комментариями. Доступ: владелец, участник, `admin`.

Ответ: `204 No Content`, тело пустое.

## Комментарии

### GET /tasks/{task_id}/comments

Комментарии к задаче. Доступ: по доступу к проекту.

Параметры запроса: `limit`, `offset`.

Ответ (200 OK): массив объектов [Comment](#модели-данных).

### POST /tasks/{task_id}/comments

Добавление комментария. Автором становится текущий пользователь. Доступ: по доступу к проекту.

Тело запроса:

```json
{
  "body": "Начала писать, нужен план"
}
```

Ответ (201 Created): объект [Comment](#модели-данных).

### PATCH /comments/{comment_id}

Изменение текста комментария. Доступ: автор, `admin`.

Тело запроса:

```json
{
  "body": "Начала писать, план готов"
}
```

Ответ (200 OK): объект [Comment](#модели-данных).

### DELETE /comments/{comment_id}

Удаление комментария. Доступ: автор, `admin`.

Ответ: `204 No Content`, тело пустое.

## Ошибки

Ошибки возвращаются в JSON с полем `detail`:

```json
{
  "detail": "Task not found"
}
```

| Код | Когда возникает |
| --- | --- |
| 401 | токен не передан, недействителен, либо аккаунт заблокирован |
| 403 | токен верный, но прав на действие нет |
| 404 | объект не найден или недоступен пользователю (существование чужих объектов не раскрывается) |
| 409 | конфликт данных, например e-mail уже зарегистрирован |
| 422 | некорректные входные данные: формат e-mail, обязательные поля, недопустимые значения `status` и `priority` |
